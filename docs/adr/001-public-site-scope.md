# ADR 001: 公開サイトの守備範囲

## Status

Accepted (2026-05-01)

## Context

Auto-Pipeline で完成したアプリを公開カタログサイトにエントリする際、公開サイトが担う範囲をどこまでとするか決める必要があった。主な選択肢は「カタログ表示のみ」と「各アプリのリバースプロキシまで含む」の2つ。

## Decision

公開サイトはカタログコンテナのみとする。

- 公開サイトはアプリ一覧 (名前・概要・リンク・タグ) を表示するカタログページ
- 各アプリは別ホスト・別 Compose スタックで個別にホスティング
- カタログから各アプリへはリンクで遷移。カタログがリバースプロキシになることはない
- 各アプリの公開 URL は Cloudflare Tunnel または AWS で割り当てる (インフラは案件ごとに判断)

## Consequences

- 公開サイト自体はシンプルな静的 / SSG サイトとして実装できる
- 各アプリの障害が公開サイトに波及しない
- 各アプリのデプロイはそれぞれ独立しており、技術スタック・ポートを自由に選べる
- カタログに表示するメタ情報 (URL 等) はアプリデプロイ後に手動または自動で登録が必要
